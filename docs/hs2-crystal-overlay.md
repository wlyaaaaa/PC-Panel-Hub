# HS2 Crystal Overlay

## 定位

`HS2 Crystal Overlay` 是给 LIAN LI HS2 2288×1048 曲面 OLED 使用的
Windows 浮层。它只负责低频、非重复信息；原有 480×1920 TURZX 副屏继续负责
密集硬件监控。

- Wallpaper Engine 或 Windows 静态图片负责背景。
- 浮层不依赖 Wallpaper Engine；动态壁纸退出后，浮层仍会显示在 Windows
  当前背景上。
- 浮层只会选择非主屏的 2288×1048 显示器。即使 `DISPLAY20` 编号被主屏
  占用，也不会在主屏创建卡片。
- 画面按实际物理像素规划：左侧约 2/3 是主要阅读区；只有信息拥挤时，
  右侧约 1/3 才承接与正面同排的短卡片。卡片不会跨越曲面折线。
- 没有全屏透明窗口、任务栏按钮或鼠标交互依赖。

## 实际视觉

浮层使用逐像素 Alpha 的透明水晶材质：只有卡片范围存在极淡洗色、折射感
描边和文字阴影，不存在黑色全屏底板。手机电量是无底板的直接叠加，并带
OLED 防烧屏微位移。

时钟和手机电量是无底板直接叠加。其余信息进入最多六张的自适应水晶卡片舞台：
只有真实内容才创建可见卡片，少量内容贴底收拢，不留下空框；满载时为三行，
正面保留宽卡，侧面只与正面卡片配对。卡片使用稳定事件绑定和平滑补位，长文本
保持大字号并在卡内滚动，不用缩字或省略号隐藏正文。

## 已实现的信息与寿命

| 信息 | 数据源 | 行为 |
| --- | --- | --- |
| 时钟 | 中国标准时间（UTC+8） | 默认显示且只显示 `HH:mm`；启动和解锁时立即校准，之后按整分钟边界刷新；`Win+F2` 切换常驻/隐藏并记住状态，不显示秒、日期、天气或日程 |
| 网易云歌曲、歌手、封面、双语歌名 | 网易云当前播放窗口、播放列表、音频会话 | 播放时以紧凑卡片常驻，切歌扩展 8 秒；不显示无法可靠同步的歌词、进度条或已播/总时长 |
| Steam 游戏名称、封面、当前时长、退出总结 | Steam 本地清单和进程日志 | 游戏运行时常驻；启动时间统一换算为中国标准时间并标注 `UTC+8`；退出总结累计可见 60 秒；不显示 FPS |
| 音量、静音 | Windows 默认控制台音频端点的实时通知 | 只显示自适应扬声器图标和 Windows 同值百分比；静音时只显示静音状态；操作后显示 6 秒，不显示设备名 |
| U 盘接入/断开、网络断开/恢复 | TURZX 本地快照、Windows 网络状态 | 显示 12 秒；网络断开须连续确认，不把 `connecting`/`stale` 当故障 |
| 主动登记的复制、下载、渲染、安装任务 | 本机命名管道 | 任务期间按租约常驻，显示完成度和预计剩余；完成提示累计可见 15 秒 |
| 水泵、CPU/GPU/内存/磁盘温度、磁盘健康/空间、长期断网告警 | TURZX 快照、LibreHardwareMonitor | 仅异常时常驻，恢复后提示 10 秒 |
| 手机电量、充电状态 | 小米妙享界面/近期本地日志；手机连接后台伴随数据/界面 | 两个源始终独立探测；仅连接时无底板常驻，小米有效且与手机连接同等新鲜时优先，否则选择证据更新的手机连接；小米界面电量会合并近期日志中的充电趋势 |
| 普通通知、来电、动态状态、跨设备传输 | Windows 通知中心中的小米妙享和手机连接通知 | 两个后台源同时接收；“新消息”“你有一个新消息”等没有实际正文的占位通知会被过滤；普通通知和动态状态各显示最多 60 个可见秒，连接状态显示 5 个可见秒；来电或活动传输只在源通知仍活动时显示，并带 5 分钟失联保护；启动时不翻出普通旧通知，但会恢复仍活动的来电/传输 |
| 手机验证码 | 小米妙享和手机连接通知 | 只在验证码语义明确时提取最新的 4–8 位数字（通常 6 位），以比标题明显更大的等宽数字显示 15 个可见秒；卡片保持紧凑且留在正面阅读区，不做全屏接管 |

“来源”和“降级”相互独立：小米妙享与手机连接每轮都会各自采集，单个源异常
不会跳过另一个源。实时界面与后台伴随文件分别保留“证据时间”和“最近确认时间”：
短暂读取失败可保留最近确认值，但重复读取旧日志不会伪造新的电量证据。两个源都
可用且证据时间接近时优先小米妙享；另一源明显更新时选更新者。未连接、无数据或
确认过旧时完全不显示。台式机电池不是支持字段。

硬件快照在传感器初始化期间可能短暂返回 `null` 或非数字状态；这些字段按暂不可用
跳过，不会中断其余温度、磁盘、水泵和网络告警。

## 优先级与恢复

全局最多显示六张水晶卡。硬件故障、来电和活动传输优先；正在播放的网易云、
正在运行的 Steam 与最新一条手机通知在普通压力下保证保留。文件传输、重要任务、
音量、U 盘和网络事件各自作为独立卡片参与六卡选择，不再挤进一个固定“活动框”。
除只代表当下操作的音量卡外，被高优先级内容暂时挤出的计时卡暂停可见计时；空间
恢复且仍未超过三分钟墙钟寿命时才回来。

手机通知只保留到达顺序最新的三条，第四条到来时立即淘汰最旧一条。无论其他卡片
如何竞争，只要仍有手机候选，最新一条就不会被挤掉。通知的 60 秒只累计真正画在
屏幕上的时间；极长正文在卡内平滑滚动。同一个 Windows 通知 ID 更新不会重置计时。
布局按时间从下向上排列：最新通知优先占最下层，第二、第三条依次向上。音量卡在
没有通知时优先使用最下、最左的紧凑槽；有通知占用时才自动使用同排下一个真实槽，
不会用固定坐标、假卡或空占位维持版式。

手机通知的标题和正文先做 Unicode 宽度、大小写、空白和标点标准化，再按字符相似度
去重；数字序列不同（例如验证码、金额）一律视为不同通知。同源或跨小米妙享/手机
连接的近似重复都覆盖三分钟队列寿命，因此错峰转发也只显示一张。运行前已存在的
普通通知只建立基线，不会在开机时翻出旧消息；仍在进行的来电和传输会恢复显示。
两个来源退到后台仍由 Windows 通知中心继续采集；若通知访问持续失联，活动来电或
传输会在 5 分钟安全租约后收起，不会永久占卡。

验证码使用固定卡片身份：新验证码会在原位置替换旧码并重新计时；同一个码经小米
妙享和手机连接重复转发时只显示一次，也不会借重复通知延长 15 秒。验证码不占普通
手机通知最多三条的配额，但仍计入全局六卡上限并受硬件告警、来电等更高优先级约束。
识别器要求验证码/OTP 等明确上下文，并排除订单号、手机号、日期、取件码、邀请码和
优惠码等数字，避免因为通知里碰巧出现 4–8 位数字就放大错误内容。运行日志不记录
验证码正文。

`Win+F1` 清除可清除的手机通知、短操作、完成提示和游戏总结，但保留正在播放的
音乐、正在运行的游戏/任务/传输、来电及硬件告警；清除后的同一中继通知会在抑制窗
内保持隐藏。`Win+F2` 切换时钟，`Win+F3/F4` 不占用。

## 网易云媒体身份边界

当前歌曲身份不再按缓存文件的修改时间猜测。应用会读取网易云仍保留的当前
播放窗口标题，与播放列表中的完整歌名和全部歌手精确匹配。多歌手分隔符只
忽略 `/` 两侧空格；同名同歌手的多个版本只在这组精确候选中按对应歌词缓存
的新鲜度消歧。仍存在歧义或无法精确匹配时暂时隐藏媒体卡片，避免把预加载
歌曲的信息混入当前播放歌曲。

实机拖动验收确认，当前网易云版本没有向本程序提供一个可审计、能随拖动立即
重定位的权威播放位置源。因此主浮层主动不显示歌词、翻译歌词、进度条以及
已播/总时长，也不再连接播放位置桥。仓库中保留的桥接工程仅是未启用的兼容
与诊断代码，不属于当前媒体卡片运行链。

## 主动任务入口

长任务不会猜测所有系统进程，必须由发起任务的脚本显式登记：

```powershell
C:\path\to\PC-Panel-Hub\tools\hs2_crystal_overlay\Publish-HS2Task.ps1 `
  -Id copy-photos `
  -Title "复制照片" `
  -Detail "正在写入归档盘" `
  -ProgressPercent 42 `
  -RemainingMinutes 3
```

完成时用相同 `Id` 并传入 `-State completed`；取消时传入
`-State cancelled`。活动任务默认租约为 5 分钟，更新进度会自动续租；超过 5 分钟
的任务应至少每 5 分钟再次用相同 `Id` 上报，或通过 `-LeaseMinutes` 明确延长。
生产者异常退出后租约会自动清除卡片，不会永久残留。同一 `Id` 重开时会先清除旧的
“已完成”提示。

## 架构

- `HS2.CrystalOverlay.Core`
  - 事件契约、优先级、寿命、去重、布局、解析和告警规则。
  - 不依赖显示器，可做确定性单元测试。
- `HS2.CrystalOverlay`
  - 打包的 WinUI 3 桌面应用。
  - 负责无激活、鼠标穿透的逐像素透明窗口和各本地数据适配器。
  - 单实例；登录启动时等待 OLED 最多约 60 秒，绝不回退到主屏。
- `HS2.NeteasePlaybackBridge`
  - 未启用的兼容与诊断工程；主浮层运行时不连接它。

## 明确边界

- Steam 成就尚未接入：当前机器没有稳定、可审计且不要求 Web API 密钥的
  本地成就事件源，因此不会伪造或轮询不可靠文件。
- 非 Steam 游戏尚未做通用识别。
- 手机通知只覆盖 Windows 通知中心真实提供的小米妙享和手机连接事件；两条
  来源链都可在中继应用退到后台后继续工作。
- HS2 作为 Windows 副显示器工作时，看门狗会动态识别浮层所在显示器，并把
  误入 HS2 的普通应用无激活地搬回主屏；若主屏真实断开到只剩 HS2，则先将
  普通应用最小化。HS2 浮层、Wallpaper Engine 和桌面外壳窗口不会被移动。
  鼠标边界仍保持 Windows 原生行为。
- 背景降级由 Windows/Wallpaper Engine 负责，本程序不修改壁纸设置。

## 验收要求

本地视觉验收可用 `--demo=<场景>` 启动打包应用；除 `media`、`notification`、
`stack`、`game`、`task`、`system`、`call` 和 `alert` 外，还提供 `max-six`、
`sparse`、`reflow`、`overflow`、`system-mute`、`audio-phone`、`audio-media`
与 `phone-order`。`max-six` 用三条手机通知、Steam、网易云和音量 HUD 验证
2288×1048 满载构图；其余场景验证静音、缺项收拢、通知时序、自适应让位、重排和
超长文本。所有演示值都是合成数据，正常无参数启动不进入演示模式。

- 单元测试覆盖优先级、寿命、恢复、去重、网易云歌曲身份匹配、UTC+8 整分钟
  对齐、Steam 跨时区及夏令时解析、网络防误报、显示器安全选择和兼容协议校验。
- 应用与兼容工程均零警告构建。
- 实机只在 2288×1048 OLED 显示；Wallpaper Engine 继续在其下方播放。
- 网易云播放时只显示正确的歌曲身份、歌手和封面；没有歌词、进度条或时间；
  暂停、切歌和退出后正确收起或更新。
- 普通通知按时消失，活动状态移除后结束，重要任务完成后只提示一次；满载始终
  不超过六卡，最新手机通知在最下层，侧面卡不跨折线，缺项后无空洞。
- 音量连续变化与静音切换只更新同一张卡，最终百分比与 Windows 一致；无设备名、
  “系统音量”或来源标签；没有手机通知时默认位于最下、最左，出现通知后自适应让位。
- 时钟只含中国标准时间的时与分，在整分钟边界翻页；`Win+F1` 清场不复活已清
  通知，`Win+F2` 可重复切换时钟且重启后保留状态。
- 原 480×1920 TURZX 心跳和遥测继续健康。
- 强制重启后若 HS2 控制器暂未枚举，未验证阶段不反复启动浮层；恢复只触及精确
  的 HS2 USB 拓扑或一次 L-Connect 服务重绑定；服务进入 Running 不算恢复，仍会
  等待控制器真实回归并在 90 秒有界窗口内每 5 秒重试。读回 Active 后会将跨越
  显示器掉线而幸存的旧浮层进程重建一次，避免进程存在但仍绑定旧显示坐标。

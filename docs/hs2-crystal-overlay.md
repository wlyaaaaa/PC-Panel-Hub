# HS2 Crystal Overlay

## 定位

`HS2 Crystal Overlay` 是给 LIAN LI HS2 2288×1048 曲面 OLED 使用的
Windows 浮层。它只负责低频、非重复信息；原有 480×1920 TURZX 副屏继续负责
密集硬件监控。

- Wallpaper Engine 或 Windows 静态图片负责背景。
- 浮层不依赖 Wallpaper Engine；动态壁纸退出后，浮层仍会显示在 Windows
  当前背景上。
- 浮层只会选择非主屏的 2288×1048 显示器。即使 `DISPLAY20` 编号被主屏
  占用，也不会在主屏创建卡片。
- 画面按实际物理像素规划：左侧约 2/3 为正面信息区，右侧约 1/3 保留给
  曲面侧面和河流壁纸。
- 没有全屏透明窗口、任务栏按钮或鼠标交互依赖。

## 实际视觉

浮层使用逐像素 Alpha 的透明水晶材质：只有卡片范围存在极淡洗色、折射感
描边和文字阴影，不存在黑色全屏底板。手机电量是无底板的直接叠加，并带
OLED 防烧屏微位移。

媒体常驻卡片为 820×176 像素，切歌提示为 940×210 像素；时钟是无底板
直接叠加，通知使用独立的弹性卡片轨道。所有卡片都限制在正面信息区，不污染
右侧河流和曲面转折区。

## 已实现的信息与寿命

| 信息 | 数据源 | 行为 |
| --- | --- | --- |
| 时钟 | 中国标准时间（UTC+8） | 默认显示且只显示 `HH:mm`；启动和解锁时立即校准，之后按整分钟边界刷新；`Ctrl+Alt+G` 切换常驻/隐藏并记住状态，不显示秒、日期、天气或日程 |
| 网易云歌曲、歌手、封面、双语歌名 | 网易云当前播放窗口、播放列表、音频会话 | 播放时以紧凑卡片常驻，切歌扩展 8 秒；不显示无法可靠同步的歌词、进度条或已播/总时长 |
| Steam 游戏名称、封面、当前时长、退出总结 | Steam 本地清单和进程日志 | 游戏运行时常驻；退出总结 20 秒；不显示 FPS |
| 音量、静音、输出设备 | Windows 音频会话 | 操作后显示 6 秒 |
| U 盘接入/断开、网络断开/恢复 | TURZX 本地快照、Windows 网络状态 | 显示 12 秒；网络断开须连续确认，不把 `connecting`/`stale` 当故障 |
| 主动登记的复制、下载、渲染、安装任务 | 本机命名管道 | 任务期间常驻，显示完成度和预计剩余；完成提示 15 秒 |
| 水泵、CPU/GPU/内存/磁盘温度、磁盘健康/空间、长期断网告警 | TURZX 快照、LibreHardwareMonitor | 仅异常时常驻，恢复后提示 10 秒 |
| 小米妙享手机电量、充电状态 | 小米妙享当前界面，近期本地日志为降级 | 仅连接时无底板常驻；小米不可用才降级到手机连接 |
| 手机连接、普通通知、来电、动态状态、跨设备传输 | Windows 通知中心中的小米妙享/手机连接通知 | 普通通知和动态状态各显示最多 10 个可见秒，连接状态显示 5 个可见秒；来电或活动传输只在源通知仍活动时显示；启动时不会翻出旧通知 |

手机电量的优先级固定为“小米妙享 > 手机连接”。未连接、无数据或数据过旧
时完全不显示。台式机电池不是支持字段。

## 优先级与恢复

硬件故障最高，其次是来电和活动传输，再到手机通知、重要任务、系统操作、
媒体、游戏和时钟。高优先级事件只暂时遮住低优先级状态；事件结束后，仍在
进行的音乐、游戏或任务会自动回来。

手机通知不再抢占音乐卡片：空间充足时同时显示两张并排卡片，其余按到达顺序
排队；空间只够一张时自动改成单列。通知时长只计算真正画在屏幕上的
时间，被来电或硬件告警临时挡住时暂停计时。卡片高度按正文自动增长；极长
正文在卡片内部平滑纵向滚动，不用省略号截断。同一个 Windows 通知 ID 在
通知中心的一次存活期内只弹一次，正文更新和重复发布都不能重置既定时长；从未
获得显示机会且排队超过 1 分钟的旧通知会直接丢弃。

小米妙享和手机连接收到内容相同的通知时，会按应用、标题和正文的标准化
指纹去重。运行前已存在的通知只建立基线，不会在开机时重复弹出。

## 网易云媒体身份边界

当前歌曲身份不再按缓存文件的修改时间猜测。应用会读取网易云仍保留的当前
播放窗口标题，与播放列表中的完整歌名和全部歌手精确匹配。多歌手分隔符只
忽略 `/` 两侧空格；同名同歌手的多个版本只在这组精确候选中按对应歌词缓存
的新鲜度消歧。仍存在歧义或无法精确匹配时暂时隐藏媒体卡片，避免把预加载
歌曲的信息混入当前播放歌曲。

实机拖动验收确认，当前网易云版本没有向本程序提供一个可审计、能随拖动立即
重定位的权威播放位置源。因此主浮层主动不显示歌词、翻译歌词、进度条以及
已播/总时长，也不再连接播放位置桥。仓库中保留的桥接工程仅是未启用的兼容
与诊断代码，不属于当前媒体卡片运行链。

## 主动任务入口

长任务不会猜测所有系统进程，必须由发起任务的脚本显式登记：

```powershell
E:\Projects\Tools\TURZX-SideScreen\tools\hs2_crystal_overlay\Publish-HS2Task.ps1 `
  -Id copy-photos `
  -Title "复制照片" `
  -Detail "正在写入归档盘" `
  -ProgressPercent 42 `
  -RemainingMinutes 3
```

完成时用相同 `Id` 并传入 `-State completed`；取消时传入
`-State cancelled`。

## 架构

- `HS2.CrystalOverlay.Core`
  - 事件契约、优先级、寿命、去重、布局、解析和告警规则。
  - 不依赖显示器，可做确定性单元测试。
- `HS2.CrystalOverlay`
  - 打包的 WinUI 3 桌面应用。
  - 负责无激活、鼠标穿透的逐像素透明窗口和各本地数据适配器。
  - 单实例；登录启动时等待 OLED 最多约 60 秒，绝不回退到主屏。
- `HS2.NeteasePlaybackBridge`
  - 未启用的兼容与诊断工程；主浮层运行时不连接它。

## 明确边界

- Steam 成就尚未接入：当前机器没有稳定、可审计且不要求 Web API 密钥的
  本地成就事件源，因此不会伪造或轮询不可靠文件。
- 非 Steam 游戏尚未做通用识别。
- 手机通知只覆盖 Windows 通知中心真实提供的小米妙享和手机连接事件。
- 主屏关闭后的窗口迁移、鼠标限制和显示拓扑救援不属于本程序；按用户决定
  保持 Windows 原生行为。
- 背景降级由 Windows/Wallpaper Engine 负责，本程序不修改壁纸设置。

## 验收要求

本地视觉验收可用 `--demo=<场景>` 启动打包应用；支持 `media`、
`notification`、`stack`、`game`、`task`、`system`、`call` 和 `alert`。
`stack` 会同时发布三条合成通知，用于实机确认“两张并排、其余排队、逐批
满 10 个可见秒后消失”。所有演示值都是合成数据，正常无参数启动不进入演示模式。

- 单元测试覆盖优先级、寿命、恢复、去重、网易云歌曲身份匹配、UTC+8 整分钟
  对齐、网络防误报、显示器安全选择和兼容协议校验。
- 应用与兼容工程均零警告构建。
- 实机只在 2288×1048 OLED 显示；Wallpaper Engine 继续在其下方播放。
- 网易云播放时只显示正确的歌曲身份、歌手和封面；没有歌词、进度条或时间；
  暂停、切歌和退出后正确收起或更新。
- 普通通知按时消失，活动状态移除后结束，重要任务完成后只提示一次。
- 时钟只含中国标准时间的时与分，在整分钟边界翻页；`Ctrl+Alt+G` 可重复
  切换且重启后保留状态。
- 原 480×1920 TURZX 心跳和遥测继续健康。
